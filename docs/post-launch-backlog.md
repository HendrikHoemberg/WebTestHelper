- **Environment:** Internal company-LAN NAS running Docker Compose (`webtesthelper` + `postgres:17-alpine`), with **no direct exposure to the public internet**.

- **Pre-Launch Go-Live Baseline (Already Fixed Before Launch):**

  - *Runtime & Security:* Crash-resume `crawl_queue_item` reset, `Recorder` restricted to `ADMIN` + `POST` session start + `startUrl` origin validation + `context.route` (`file://`/loopback blocking) + `ScreencastBridge` idle-timeout fix + `RecordingSessionRegistry` context-leak fix, `StepExecutor` `http(s)` validation + `Redactor` credential masking + `PdfRenderer` network abort, `OutboxService` async `retryAllFailed` & atomic claim, `SetupController` `ADMIN`-only enforcement.

They are ordered by operational urgency after launch.

## 2. Priority 1 — Soon After Go-Live (Operational & Reliability)

### 2.1 Container Memory Budget (`2560m` vs. 4 Resident Chromium Instances)
- **Locations:** `compose.yaml:28-34`, `Dockerfile:41`, `src/main/resources/application.properties:36`, `src/main/java/dev/hendrikhoemberg/webtesthelper/recorder/RecorderWorker.java:94-104`, `src/main/java/dev/hendrikhoemberg/webtesthelper/recorder/RecordingSession.java:148-150`, `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/PdfRenderer.java:94-104`
- **Impact:** JVM `-Xmx1g` consumes ~1.3 GB total RSS, while up to **4 persistent Chromium instances** stay resident simultaneously (1 crawl worker + 2 recorder workers whose browsers are never closed when sessions end + 1 persistent PDF Chromium), plus `shm_size: 1gb` (`/dev/shm` usage counts against the container's `2560m` cgroup limit). Overlapping crawl + recorder + PDF export (or increasing `WTH_BROWSER_WORKERS` to `2`) risks container OOM-kill (`Exit 137`).
- **Recommended Fix:** Raise `limits.memory` in `compose.yaml` to `3584m–4096m`, and/or add idle browser eviction for `RecorderWorker` and `PdfRenderer` after inactivity; document the per-process memory budget inline in `compose.yaml`.

### 2.2 Scheduled PostgreSQL Table Pruning/Retention & Orphaned Artifact Cleanup
- **Locations:**
  - DB tables: `src/main/resources/db/migration/V4__run.sql`, `src/main/resources/db/migration/V7__crawl_queue_item.sql`, `src/main/resources/db/migration/V8__external_url_check.sql`, `src/main/resources/db/migration/V9__finding.sql`, `src/main/resources/db/migration/V12__notification.sql`
  - Retention & site delete: `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/ArtifactRetentionService.java:37-43`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/persistence/RunResultJdbcRepository.java:46-53`, `src/main/java/dev/hendrikhoemberg/webtesthelper/catalog/SiteService.java:77-79`
  - Setup probe artifacts: `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/SetupProbe.java:57,104-108`
- **Impact:**
  - `ArtifactRetentionService` only deletes screenshot directories on disk; nothing ever prunes PostgreSQL rows from `crawl_queue_item` (300–15,000 rows/run, unused post-run), `finding_occurrence` (per finding × page × run with JSONB `evidence`), `notification` (full HTML/text bodies forever), `external_url_check` (expired cache rows never swept despite `ix_external_url_check_checked_at`), or `run` (`covered_urls` JSONB).
  - `RunResultJdbcRepository.findExpiredArtifactRunIds` re-queries every historical run beyond rank 12 nightly and `stat()`s disk for all of them.
  - Deleting a site (`SiteService.delete`) cascade-deletes `run` rows without removing `/data/artifacts/<runId>/`, permanently orphaning screenshots and Playwright trace zips.
  - `SetupProbe` writes up to 8 PNGs per probe into `data/artifacts/probe/` and never deletes them.
- **Recommended Fix:** Add scheduled DB pruning (e.g., `crawl_queue_item` for terminal runs >7 days, `SENT` `notification` >90 days, expired `external_url_check` >14 days, and an archival/retention policy for old `finding_occurrence` rows). Track pruned runs (or iterate only existing numeric directories in `/data/artifacts/`) so retention stays O(recent runs). Delete a site's artifact directories on `SiteService.delete` and sweep numeric dirs whose `runId` no longer exists in `run`. Delete probe screenshots after capture (matching `CrawlService.deleteProbeScreenshot`) or skip saving PNGs during setup probes.

### 2.3 `/data/keyfile` Backup Runbook & Optional Separation from `artifacts/`
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/catalog/SecretBox.java:36-78`, `src/main/java/dev/hendrikhoemberg/webtesthelper/catalog/AppSettings.java:86-88`, `compose.yaml:21-22`, `Dockerfile:38`
- **Impact:** The AES-256 master key `/data/keyfile` shares volume `wth-data` with prunable `/data/artifacts/`. If NAS backups cover only `pgdata` (treating `/data` as disposable screenshots) or `wth-data` is recreated, all encrypted `credential.secret` rows and SMTP/IMAP passwords become permanently undecryptable (`AppSettings.java:86-88` silently falls back to `null` passwords). Future container UID changes can also break reads of a `0600` keyfile.
- **Recommended Fix:** Write a NAS backup/restore runbook explicitly requiring synchronized backups of `pgdata` and `/data/keyfile` (with ownership/mode checks), and optionally support a dedicated secret volume or `WTH_MASTER_KEY_FILE` path separated from `artifacts/`.

### 2.4 Outbound SSRF Hardening for External Redirects into Company LAN
- **Locations:**
  - HTTP clients & probes: `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/UrlVerifier.java:44-47,130-166`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/SiteResourceFetcher.java:21-38`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/CrawlService.java:364-374,411-427`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/TlsProbe.java:34-54`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/UrlAdmission.java:63-71`
  - Playwright crawlers: `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/PageNavigator.java:124-147`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/InteractionRunner.java:143-201`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/JourneyReplayer.java`
  - Site registration & webhooks: `src/main/java/dev/hendrikhoemberg/webtesthelper/catalog/SiteService.java:46-75`, `src/main/java/dev/hendrikhoemberg/webtesthelper/web/SiteFormModel.java:22-24`, `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/WebhookNotifier.java:46-89,321-328`
- **Impact:** `WebhookNotifier.isBlockedIp()` is currently unused outside webhooks. Any crawled external website linking or HTTP-30x redirecting (`HttpClient.Redirect.NORMAL`) to internal NAS/LAN RFC1918 hosts, loopback, or metadata IPs is probed by `UrlVerifier` (which persists up to 1024 bytes of response body + headers into finding evidence), fetched by `SiteResourceFetcher`, probed by `TlsProbe`, and navigated by Playwright (with `ignoreHTTPSErrors=true`). In `WebhookNotifier`, DNS is resolved in `validateWebhookUrl()` and again by `HttpClient` on connect (DNS-rebinding TOCTOU).
- **Recommended Fix:** Extract a shared SSRF egress validator reusing `WebhookNotifier.isBlockedIp()`. Switch `UrlVerifier`, `SiteResourceFetcher`, and `WebhookNotifier` to `Redirect.NEVER` with per-hop IP validation and IP pinning (custom DNS/connect check) to stop redirects and DNS rebinding. Add `context.route(...)` egress checks to Playwright contexts (`PageNavigator`, `InteractionRunner`, `JourneyReplayer`). Provide an explicit `WTH_ALLOW_PRIVATE_TARGETS` flag (or host allowlist) so admins can still intentionally monitor internal company-LAN services without weakening protection against untrusted external redirects.

### 2.5 Lease Heartbeats & Cancellation Checks Inside Long Post-Crawl Phases
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/CrawlRunExecutor.java:126-181`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/UrlVerifier.java:91-118`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/InteractionRunner.java:115-129`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/JourneyPass.java:70-97`
- **Impact:** Lease heartbeats and cancellation checks only execute between top-level phases, not inside `verifier.verify`, `interactionRunner.run`, `journeyPass.run`, or `reverifier.reverify`. On large sites with many slow/dead external links (10s `HEAD` + 10s `GET` fallback per host) or multiple interaction targets/journeys, a single phase can exceed the 30-minute lease or ignore user cancellation for tens of minutes, letting `LeaseReclaimJob` reclaim an active run.
- **Recommended Fix:** Run a scoped periodic lease heartbeat for the duration of an active run (interrupting execution if the lease is lost) and poll cancellation between verification batches, interaction targets, and journeys.

### 2.6 `CrawlService.seedFrontier()` Deduplication, Batching, Size Caps & Cancellation
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/CrawlService.java:362-382`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/SiteResourceFetcher.java:34`
- **Impact:** `sitemapUrls` is declared as an `ArrayList` (`CrawlService.java:362`), so `if (sitemapUrls.add(url.value()))` (`CrawlService.java:368`) always returns `true` and never deduplicates across up to 10 child sitemaps. Each URL executes a separate DB `INSERT` (`frontier.enqueue(runId, List.of(url), ...)`) without checking cancellation, and `SiteResourceFetcher.fetchText` reads unbounded HTTP response bodies via `BodyHandlers.ofString()`. Large sitemaps (50k–500k URLs or multi-MB XML) cause severe latency and heap spikes.
- **Recommended Fix:** Replace `ArrayList` with `LinkedHashSet<String>`, batch `frontier.enqueue` in chunks (e.g. 500 URLs), cap response bytes in `SiteResourceFetcher` (e.g. 10 MB) and total seeded sitemap URLs, and check cancellation during seeding.

### 2.7 Graceful `BrowserPool.close()` Interruption Ordering
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/BrowserPool.java:143-150,170-183`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/CrawlService.java:151-191`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/RunPoller.java:42-55`
- **Impact:** During shutdown, `RunPoller.stop()` interrupts `run-poller` and virtual threads blocked in `BrowserPool.Worker.call` → `future.get()`, which does not cancel the worker's `Future`. `@PreDestroy BrowserPool.close()` then queues `closeQuietly` behind a still-running 30s navigation on the single-thread executor and waits 5s; on `TimeoutException`, `thread.shutdownNow()` interrupts the executor and `closeQuietly()` never runs, risking orphaned Playwright Node/Chromium processes until container termination.
- **Recommended Fix:** Cancel the worker's `Future` on `InterruptedException` in `BrowserPool.Worker.call`, and in `BrowserPool.close()` interrupt in-flight work before running `closeQuietly()` so Playwright shuts down its driver and Chromium cleanly.

## 3. Priority 2 — Hardening, UX & German Copy Polish

### 3.1 Session Invalidation on User Disable, Demotion, Password Change, or Deletion
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/web/SecurityConfig.java:24-58`, `src/main/java/dev/hendrikhoemberg/webtesthelper/web/UserController.java:72-107`, `src/main/java/dev/hendrikhoemberg/webtesthelper/auth/AppUserService.java:64-96`, `src/main/java/dev/hendrikhoemberg/webtesthelper/recorder/RecordingSessionRegistry.java`
- **Impact:** `SecurityContext` is cached in `HttpSession` (`loadUserByUsername()` only runs at login). Disabling, demoting, deleting, or resetting the password of an existing user leaves their active `ROLE_ADMIN` HTTP session and open recorder WebSocket sessions usable until expiry.
- **Recommended Fix:** Wire Spring Security's `SessionRegistry` (or Spring Session) and expire all sessions for the affected username — and call `RecordingSessionRegistry.closeAllForUser(...)` — on `setEnabled(false)`, `setRole`, `setPassword`, and `delete`.

### 3.2 SMTP/IMAP TLS Hardening (`starttls.required` & `ssl.checkserveridentity`)
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/EmailNotifier.java:68-82`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/ImapMailbox.java:126-143`, `src/main/java/dev/hendrikhoemberg/webtesthelper/web/SettingsController.java:221-238`
- **Impact:** `EmailNotifier` sets `mail.smtp.starttls.enable=true` without `mail.smtp.starttls.required=true`, allowing silent downgrade to plaintext SMTP if STARTTLS is not offered. Neither SMTP nor IMAP enables `mail.<proto>.ssl.checkserveridentity=true` (Jakarta/Angus Mail defaults to `false`), skipping TLS hostname verification.
- **Recommended Fix:** Set `mail.smtp.starttls.required=true` in `STARTTLS` mode and `mail.<proto>.ssl.checkserveridentity=true` across `EmailNotifier`, `ImapMailbox`, and `SettingsController`.
- **LAN / Self-Signed Relay Note:** If the company LAN uses an internal mail relay with a self-signed or hostname-mismatched certificate, mount the company root CA into the JVM truststore or expose an explicit opt-out toggle before enforcing strict hostname verification.

### 3.3 `DigestService` Per-Scope Transactions, Post-Commit Webhooks & Non-2xx Logging
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/DigestService.java:28,62-123`, `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/WebhookNotifier.java:341-372`
- **Impact:** All 3 digest scopes execute inside one `@Transactional` method without atomic row claiming (risking duplicate digests if >1 instance ever runs) while invoking `webhookNotifier.sendDigestNotificationAsync` (including synchronous DNS resolution in `validateWebhookUrl`) before transaction commit — a failure in a later scope rolls back `markDigested` for earlier scopes after their webhooks already fired. `DigestService` also ignores the returned `CompletableFuture`, and `WebhookNotifier.postPayloadAsync` does not log non-2xx HTTP status codes, making HTTP 4xx/5xx webhook errors completely silent.
- **Recommended Fix:** Run each scope in its own transaction, claim runs atomically (conditional `markDigested` checking row count or `FOR UPDATE SKIP LOCKED`), fire webhooks after commit (or via outbox), and log non-2xx webhook responses with status and endpoint details.

### 3.4 `PageSnapshot` Memory Reduction & Server-Side Form Upper Bounds
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/CrawlService.java:144`, `src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/PageNavigator.java:120-143`, `src/main/resources/crawler/extract.js:180`, `src/main/java/dev/hendrikhoemberg/webtesthelper/model/PageSnapshot.java:23`, `src/main/java/dev/hendrikhoemberg/webtesthelper/web/SiteFormModel.java:26-36`, `src/main/java/dev/hendrikhoemberg/webtesthelper/web/JourneyEditController.java:109`, `src/main/java/dev/hendrikhoemberg/webtesthelper/runner/StepExecutor.java:235`
- **Impact:** Every `PageSnapshot` keeps full `document.body.innerText` in heap for the entire crawl (callers only check `.isBlank()` and `.length()`) plus uncapped `console` and `failed` lists. Meanwhile, `SiteFormModel` has `@Min(1)` with no `@Max` on `maxPages`/`maxDepth`/`maxDurationMinutes`, `JourneyEditController` has no server-side cap on `timeoutMs` or step count, and `StepExecutor.java:235` compiles unbounded admin regexes for `URL_MATCHES` (ReDoS risk).
- **Recommended Fix:** Store `textLength` instead of full `textContent` after computing `SimHash`, cap `console`/`failed` lists per page (e.g. 200 entries), add `@Max` bounds on `SiteFormModel` and `JourneyEditController` (e.g. max steps & max timeout), and bound `URL_MATCHES` regex length/complexity.

### 3.5 Secondary Runtime Reliability Fixes
- **`InteractionRunner` deadline propagation** (`src/main/java/dev/hendrikhoemberg/webtesthelper/runner/InteractionRunner.java:222-236`, `src/main/java/dev/hendrikhoemberg/webtesthelper/checks/ButtonReachabilityCheck.java:91,112-236`, `src/main/java/dev/hendrikhoemberg/webtesthelper/checks/ContactFormCheck.java:86-88,261-325`): `page.setDefaultTimeout(effectiveTimeout)` only bounds single Playwright calls; if a multi-step check finishes slightly past `effectiveTimeout`, line 231 silently drops all collected findings and omits driven coverage. Pass an explicit deadline into interaction checks so multi-step loops stop early within budget and retain already-collected findings.
- **`ScreencastBridge` / `IntentCapture` disconnect cleanup** (`src/main/java/dev/hendrikhoemberg/webtesthelper/recorder/RecordingSessionRegistry.java:125-140`, `src/main/java/dev/hendrikhoemberg/webtesthelper/recorder/ScreencastBridge.java:171-186,193-236`, `src/main/java/dev/hendrikhoemberg/webtesthelper/recorder/RecorderSocketHandler.java:82-100,133-146`): Reaping an open session closes the browser context and returns the `RecorderWorker` to `RecorderPool` without detaching `ScreencastBridge` or closing the `WebSocketSession` (leaking `activeAttachments`/`historicalAcks` and racing the pump thread against the released worker). WebSocket reconnects also register duplicate `IntentCapture` listeners without cleanup. Detach `ScreencastBridge` and close the socket before releasing the worker in `RecordingSessionRegistry.close()`, and remove the `IntentCapture` listener in `afterConnectionClosed`.
- **`ImapMailbox` scoped search, transient retry & retention** (`src/main/java/dev/hendrikhoemberg/webtesthelper/runner/ImapMailbox.java:61-101,154-162`): `folder.search(new BodyTerm(token))` scans the entire `INBOX` on every poll (up to 7× per check) and aborts on a single transient IMAP error. As DEEP test emails accumulate over months, searches will exceed the 10s `mail.imap.timeout` and cause `ContactFormCheck` to abstain. Scope searches with `AndTerm(new ReceivedDateTerm(ComparisonTerm.GE, ...), new BodyTerm(token))` (or `UNSEEN`), add mailbox cleanup/retention, and tolerate transient poll failures within the 60s wait budget.
- **`OutboxDispatcher` per-item exception isolation & lease headroom** (`src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/OutboxDispatcher.java:42-68`, `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/persistence/OutboxClaimJdbcRepository.java:50`, `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/EmailNotifier.java:64-66`): An exception from `markSent`/`markRetry`/`markFailed` or `appSettings.redirectAllMailTo()` escapes the loop and abandons up to 19 remaining claimed mails for `CLAIM_LEASE` (5m), and 20 mails × 15s SMTP timeout equals the full 5m lease. Wrap each iteration in a per-item try/catch with error logging, and lower batch size (e.g. 10) or increase `CLAIM_LEASE` (e.g. 10m).

## 4. Priority 3 — Low Priority / Nice-to-Have (Especially If Ever Exposed Beyond LAN)

### 4.1 Login Brute-Force Protection / Rate Limiting
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/web/SecurityConfig.java:54`, `src/main/java/dev/hendrikhoemberg/webtesthelper/auth/AppUserService.java:21,36-38,108-120`
- **Impact:** `POST /anmelden` has no per-IP or per-account throttling/lockout; default admin username is `admin` and minimum password length is 8 characters.
- **Recommended Fix:** Add Caffeine-backed (already in `pom.xml`) per-IP and per-username progressive backoff on login failures and audit-log failed logins with client IP.

### 4.2 Strict CSP, `Referrer-Policy`, `Permissions-Policy` & `noopener`
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/web/SecurityConfig.java:25-29`, `src/main/resources/templates/befunde/detail.html:152,162`
- **Impact:** CSP currently allows `script-src 'self' 'unsafe-inline' 'unsafe-eval'` and wildcard `connect-src 'self' ws: wss:`; `Referrer-Policy` and `Permissions-Policy` headers are omitted; fullscreen screenshot link (`detail.html:152`) and `window.open` (`detail.html:162`) omit `noopener noreferrer`.
- **Recommended Fix:** Add `Referrer-Policy: strict-origin-when-cross-origin` (or `no-referrer`) and `Permissions-Policy` in `SecurityConfig`; tighten `connect-src` to `'self'`; add `rel="noopener noreferrer"` and `'noopener,noreferrer'` in `befunde/detail.html:152,162`; long-term migrate to Alpine's CSP build + external JS to remove `'unsafe-inline'`/`'unsafe-eval'`.

### 4.3 PDF Rate Limiting / Caching & `ROLE_USER` Action Review
- **Locations:** `src/main/java/dev/hendrikhoemberg/webtesthelper/web/RunController.java:151-176,186-201`, `src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/PdfRenderer.java`
- **Impact:** `GET /laeufe/{id}/bericht/pdf` synchronously occupies the single-threaded `PdfRenderer` Chromium worker (up to 30s per render) without per-user throttling or caching; `ROLE_USER` can also enqueue and cancel runs.
- **Recommended Fix:** Add per-user rate limiting or short-lived PDF response caching (keyed by run ID / snapshot state), and revisit whether `ROLE_USER` should retain run start/cancel privileges if the user base expands.

### 4.4 Minor Runtime Edge Cases
- **`TlsCertCheck` 0-day expiry boundary** (`src/main/java/dev/hendrikhoemberg/webtesthelper/checks/TlsCertCheck.java:55-65`): `ChronoUnit.DAYS.between(now, fact.notAfter())` truncates toward zero, reporting a certificate expired 1–23h ago as `EXPIRING_SOON` (`WARN`, "0 Tagen") instead of `EXPIRED` (`ERROR`). Check `if (fact.notAfter().isBefore(now))` for `EXPIRED`.
- **`UrlVerifier.head()` body stream & throttle interruption** (`src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/UrlVerifier.java:70-78,108,129-138`): `head()` uses `BodyHandlers.ofInputStream()` without closing `exchange.response().body()` — switch to `BodyHandlers.discarding()`. Also propagate cancellation or record `UNVERIFIABLE` when `HostThrottle.await` throws `CrawlCancelledException` inside virtual-thread futures instead of silently dropping those URLs.
- **`IframeEmbedCheck` null guard** (`src/main/java/dev/hendrikhoemberg/webtesthelper/checks/IframeEmbedCheck.java:110,163-164`): Add a null guard before calling `mapsCodeIn(error.text())` (matching line 93) to avoid NPE on null console error text.
- **`TlsProbe` IP-literal SNI** (`src/main/java/dev/hendrikhoemberg/webtesthelper/crawler/TlsProbe.java:44`): `new SNIHostName(baseUrl.host())` throws `IllegalArgumentException` for IP-literal HTTPS hosts; omit SNI when the host is an IP literal.
- **`SecretBox` atomic keyfile creation** (`src/main/java/dev/hendrikhoemberg/webtesthelper/catalog/SecretBox.java:58-66`): `Files.createFile` followed by `Files.write` leaves a brief 0-byte window on concurrent first boot over a shared volume where a racing instance can fail `SecretKeySpec`; write via temp file + `ATOMIC_MOVE`.
- **`PdfRenderer` `setContent` timeout & crash recovery** (`src/main/java/dev/hendrikhoemberg/webtesthelper/reporting/PdfRenderer.java:68,81-86`): Set an explicit `page.setContent` timeout below the 30s `future.get` timeout and call `closeQuietly()` on timeout/interruption so Playwright restarts cleanly instead of leaving its single-thread connection desynced.
